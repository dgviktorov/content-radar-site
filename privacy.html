Privacy Policy

Last updated: October 21, 2026

This policy explains how Content Radar accesses, uses, stores and shares Google user data. Content Radar is a personal AI editorial assistant built and used by its developer for their own blog (see the home page). It is not offered as a service to other people.

Status: the Google Drive integration described here is in development and is not enabled yet. Content Radar has not been verified by Google. This policy describes how the integration works and will be kept up to date as it changes.

1. The permission Content Radar asks for

Content Radar requests exactly one Google permission (OAuth scope):

  • https://www.googleapis.com/auth/drive.file. Google describes it as access to “only the specific Google Drive files you use with this app”. In practice, it covers only the files and folders that Content Radar itself creates.

Content Radar cannot see, open, change or delete any other file in your Google Drive. It does not request your name, email address, profile, contacts or any other Google data.

2. What Google user data Content Radar accesses

  • Folders it creates. During a one-time setup, Content Radar creates an editorial folder with an inbox folder inside it in your Google Drive (or only the inbox folder, if you prefer to place it yourself).
  • Files it creates. Each time you press the “To editorial” button on an idea card in your private Content Radar Telegram bot, Content Radar creates one Markdown file in the inbox folder. The file contains the editorial brief for that idea, prepared by Content Radar from public sources and the author's own editorial notes: the topic, why it may interest readers, a suggested angle and its reasoning, a concept, a possible opening, a format, questions for the author, facts to check before publishing, and links to and short excerpts from the source posts. Verbatim excerpts from the author's private notes are left out of these files.
  • Information about its own files and folders. Content Radar reads basic information about the files and folders it created: their ID, name, file type, parent folder, whether they are in the trash, their web link, and the private labels Content Radar attached to them (the internal idea and run numbers). It uses this only to find its own folder, confirm that a file was saved correctly and avoid creating duplicates.
  • Access tokens. When you grant the permission, Google gives Content Radar a refresh token and short-lived access tokens that allow it to make these requests.

Content Radar does not read the contents of files in your Google Drive, and it does not edit, move, share or delete files there.

3. How Content Radar uses this data

Google user data is used only to provide the feature you asked for: saving editorial briefs to your Google Drive and giving you a link to each saved file. Specifically:

  • The file ID and link are recorded in Content Radar's own database, so that it knows which ideas have already been sent and never creates the same file twice.
  • The link to the saved file is shown to you in your private chat with the Content Radar Telegram bot.

Content Radar does not use Google user data for advertising, does not sell it, and does not use it to determine creditworthiness or for lending. Google user data is not sent to AI models. Content Radar does not use data obtained through Google Workspace APIs, including the Google Drive API, to develop, improve or train generalized or non-personalized AI or machine learning models.

4. Sharing and transfer

Content Radar does not share, sell, rent or transfer Google user data to anyone, with these narrow exceptions:

  • Telegram. The link to a saved file is delivered to you through Telegram, the messaging service on which the Content Radar bot runs, in your private chat with the bot.
  • Legal requirements. If disclosure is required by applicable law.

Nobody else has access to your Google user data through Content Radar.

5. Storage and protection

  • The refresh token is stored only on the computer where Content Radar runs, in a separate file with access restricted to Content Radar's own system account. It is never stored in source code repositories, and it is never printed in logs, error messages or chat messages.
  • If an authorization attempt fails, the existing token is left unchanged; a new token replaces the old one only after a successful authorization.
  • All requests to Google are made over encrypted HTTPS connections.
  • The database with file IDs and links is kept on the same computer and is not published anywhere.

6. Retention and deletion

  • Files in your Google Drive belong to you. They stay in your Drive until you delete them, including after you revoke Content Radar's access.
  • The refresh token is kept until it is replaced or deleted. When you revoke access, Google invalidates it, and it can no longer be used.
  • File IDs and links are kept in Content Radar's database as part of the history of the idea they belong to, while Content Radar is in use. You can ask for them to be deleted using the contact below.

7. How to revoke access

You can withdraw Content Radar's access to your Google Drive at any time:

  • Open the linked apps page of your Google Account and choose the “Access to your Google Account” filter.
  • Select Content Radar, then “See details” → “Remove access” → “Confirm”.

Google's instructions: manage connections between your Google Account and third-party apps.

After that, Content Radar can no longer create files in your Drive or read information about the files it created. Files that were already saved stay in your Drive.

8. Google API Services User Data Policy

Content Radar's use and transfer to any other app of information received from Google APIs will adhere to the Google API Services User Data Policy, including the Limited Use requirements.

9. Changes to this policy

If the way Content Radar uses Google user data changes, this page will be updated before the change takes effect, and the date at the top will change.

10. Contact

Questions about this policy can be sent by opening an issue in the public repository of this site. Issues are public, so please do not include personal information in them.
